# Automatic in-game frontend

One Epic LUT package chooses a usable `DBFMCM` provider when present. Otherwise F10 opens Epic LUT's own in-game menu. The same equipped-target model, generated controls, callbacks, float documents, presets, native binding lifetime and original restoration serve both frontends. Both registries use the dedicated per-mod settings folder `%LOCALAPPDATA%/Epic LUT/settings`; there is no second authoritative settings namespace.

The fallback bundles a snapshot of the maintained DBF-MCM registry, menu, stock GUI view, storage, grouping, capture lifecycle and original-provider adapter. It does not load or register MCM itself, publish `DBFMCM`, or require the MCM mod to be installed. The input runtime shipped in the ZIP is byte-identical to the pinned input library (SHA-256 `7e9a41484881fa851184b64a7b09f568b2f42637646bc85426a89fb5fb182350`). Builds refuse a different library. Compatible MCM must advertise per-mod storage/presentation support; update the maintained MCM Lua adapter when integrating this build. Source builds take that artifact from the sibling maintained DBF-MCM checkout; a source-only clone therefore needs that build dependency, while the generated package contains the runtime.

If MCM appears, the own menu releases its input/cursor snapshot before yielding. The maintained MCM adapter checks this handoff before activation. When MCM disappears, the own frontend registers the same specification against the same settings files. No second equipped-LUT writer is created. No legacy settings or palettes are migrated or deleted. An incompatible MCM instance is reported rather than competing for its input. Failed cursor restoration retains the snapshot and defers handoff/cleanup.

General Settings appears directly beneath Epic LUT, followed by Quick Load, Armor, Helmet and the original CowboyBingus submenu when its provider is available. It includes native import, truthful source-row swatches, independent Armor/Helmet Apply and shared master toggles. Extras is collapsed by default and contains independent material/emission preservation switches, both Off. Disabling a target restores original bindings while retaining its mapped document; re-enabling uses the current target's validated retained document. A different equipped item requires Apply to map the retained imported source to that item. Reset Custom LUT Rows clears the mapped document separately.

The native file service uses the bundled Windows x64 Python runtime and codecs. File actions start it automatically; a browser is optional. Runtime extraction occurs outside the game thread. The BSL stream file and loose `runtime.zip` contain the same payload. No external Python setup is required. RAR extraction requires installed 7-Zip. Standalone means no MCM dependency; a supported loader and verified game build are still required.

The own menu supports keyboard/mouse navigation. The release uses the direct saved-key handler. The separate Bingus binding adapter remains in source for diagnostic testing and is withheld from ordinary builds. The direct-keyboard path has passed repeated user-reported launches and input/restoration tests; the precise cause of earlier failures remains unproven. The latest mip-import and grouped UI changes have the validation limits described in the release notes. A 3D armor panel needs a dedicated render surface; source-row swatches display palette data only.

Archive discovery also uses the bundled service. The game supplies only equipped kit metadata; the worker reads the installed archive files and returns validated original float DDS tables with every texture-slot reference. The game keeps texture binding and live editing ownership. No process-memory reader is used by the service.

A successful import switches the original Match Your Colors setting Off through its own provider. Cancel and invalid files leave that setting unchanged. The game-launched file service exits when the game closes or crashes. Manual browser-editor startup remains independent of game lifetime.
